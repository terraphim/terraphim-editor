# Reusable Alternative Control host framework

Approved execution scope: repair confirmed failures first, implement reusable boundary, extend the existing `vs-code-terraphim-it` extension. The Zed fork is separate. Native qualification is blocked by pointer routing; unresolved acceptance is retained while independent implementation continues.

The authoritative domain implementation remains `DocumentSession`, `terraphim_alternatives` and `terraphim_lab`. Add an instance-owned host session facade to the existing editor package: no document, role, pending operation or request counter is shared between facade instances. Keep the existing browser entry backwards compatible. A host owns persisted text, revisions, undo/redo, file dialogs and actual application of edits. The engine stages a cloned session; only an acknowledgement containing the exact proposed serialized output advances it. Rejection or external host changes invalidate the pending proposal.

Protocol v1 envelopes carry resource URI, session identity, monotonic request ID, expected host revision and SHA-256 of the exact source. UTF-16 offsets describe body operations. Responses expose serialized source plus body/annotations/counts/Overflow projections. Invalid or stale requests cannot mutate state. Native history restores whole source including its annotation block; a sync notification rebases the session from that actual source. No input fixture is recorded as successful output.

VS Code uses its existing extension package, adding an opt-in CustomTextEditorProvider. Each webview owns a separate WASM instance and the existing editor UI/assets. Document changes apply through WorkspaceEdit only after exact revision/source checks; split views synchronize from the host TextDocument. Disable browser persistence and local history ownership in host mode; route save/open/export/history to VS Code. CSP uses local assets and nonces, not remote scripts. Avoid unconditional optional NAPI imports blocking activation of the editor. Preserve existing commands.

Acceptance tests cover two documents, two views, stale providers, duplicate request IDs, cancelled proposals, external edits, Unicode/CRLF, persistent ghosts, exact clean export, annotated undo/redo and lifecycle disposal. Test the real domain implementation, WASM outputs and native VS Code; a TypeScript build is not runtime acceptance. All 41 requirements remain individually classified for each host. Stock Zed visual gaps remain unmet in this workstream.

## Portability boundaries and next adapters

The reusable components now implemented are src/host.rs (Rust/WASM exact-source sessions), public/js/host-session.js (host-neutral ACK/command/conflict protocol), and scripts/build-host-assets.py (stable local asset delivery with source hashes). Host adapters own revisions, source storage, file dialogs, native history and lifecycle. They must not reuse a singleton session, accept stale async output or serialize offsets from a different newline representation. Native CRLF output is structurally rebased; browser presentation uses LF. Conversion refuses half-CRLF boundaries and malformed annotation-block alterations.

| Host | Recommended adapter | Boundary requiring separate qualification |
|---|---|---|
| VS Code | Existing extension's opt-in CustomTextEditorProvider; shared DOM/WASM UI | Native document/edit/undo/dialog behavior and multi-view races; r8 finite outputs do not qualify r9 source |
| Sublime Text | Python plugin native commands/regions/phantoms, with a Rust companion transport if WASM execution is unavailable | minihtml phantoms are decorations, not a general browser editor; full visual panel/opacity parity must be proved separately |
| Obsidian | Existing plugin integration using CodeMirror 6 decorations/state fields, plus shared WASM domain engine | Native editor transactions/undo and vault conflicts; a custom view can reuse DOM UI but changes host editing experience |
| Logseq | Plugin UI plus explicit block-scoped adapter | Graph/block identity, ordering and multi-block edits require a transaction contract; concatenating arbitrary blocks into a pretend file is not sufficient |
| Stock Zed extension | Existing LSP transport and code actions | Custom full UI remains a separate fork workstream; LSP equivalence is not visual acceptance |

These choices are engineering inferences from official API capabilities: [VS Code custom editors](https://code.visualstudio.com/api/extension-guides/custom-editors) use webviews and shared TextDocuments; [Sublime API](https://www.sublimetext.com/docs/api_reference.html) provides regions, commands and minihtml phantoms; [Obsidian editor decorations](https://docs.obsidian.md/Plugins/Editor/Decorations) expose CodeMirror-based styling/widgets; [Logseq provideUI](https://plugins-doc.logseq.com/logseq/provideUI) exposes plugin UI. They do not prove that those hosts already implement this flow. No Sublime/Obsidian/Logseq implementation is claimed in this VS Code delivery.

Each future adapter must run the same exact-source scenarios: native input→proposal→actual acknowledged output, stale/duplicate responses, two views/documents, concurrent external edits, Unicode and CRLF, malformed/unresolved annotations, ghost/alternative/Overflow save-reopen, native history and clean repeated export. Every visual requirement also needs its host-specific observed output and timestamped recording. The 41-row acceptance contract lives in docs/verification/output-fixes-20261011/all-41-host-acceptance.json and deliberately records no blanket pass.

Additional user constraint: authored alternatives must be tracked as scoped KG synonyms using the existing Terraphim crates, not only saved in annotations. The existing implementation reads KG synonyms but does not yet register new authored ones. [The shared synonym contract](alternative-synonym-tracking.md) records the missing direction, committed-output publication rules, scope/conflict requirements and real-crate acceptance tests. This remains an explicit delivery gap, including for the r10 VS Code package.

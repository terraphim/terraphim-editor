# Summary: public/js/blocks.js

## Purpose
Blocks view (#19): a third view of the open document, alongside plain and Write_On, showing the Markdown body as editable top-level blocks.

## Key points
- `BlocksView.parse` / `BlocksView.serialise`: lossless split of the body into contiguous blocks (heading, paragraph, list, code, quote, table, rule); body -> blocks -> body is byte-identical by construction.
- No content copy: blocks are parsed on demand from the surface text, and block edits are applied as minimal diffs through `surface.replaceRange(..., { source: 'blocks' })`, so the span model, undo and preview see ordinary edits.
- Text | Blocks toolbar toggle in plain mode; no control in Write_On (entering Write_On switches to Text; Blocks resumes in plain mode). Fires `te:view-change`; the view preference (only) is in localStorage `terraphim-editor:view`.
- An open block draft is never lost: outside edits before or after the block keep the editor open (range mapped through the change); overlapping edits or document replacement (openDocument) move the draft to a non-blocking notice with Replace block (only when the block still holds the draft's original text) or Insert as new paragraph, and Discard. Escape never discards typed text (the draft goes to the same notice). `destroy()` never edits: it dispatches `te:blocks-drafts` with unapplied drafts and returns them (`pendingDrafts()` to check first).
- Keyboard navigable (roving tabindex including the focused card's action buttons, Enter/F2 to edit, Shift+Enter to add below, Escape/Ctrl+Enter, Delete, undo/redo); listeners use the editor's AbortController; `destroy()` removes its DOM. Design: `docs/design/blocks-view.md`.
- Move up / Move down (#58): `moveBlock(index, 'up' | 'down')`, the roving action buttons and Alt+ArrowUp / Alt+ArrowDown on a focused card swap a block with its neighbour through `MarkdownEditor.moveRange` (#44), so spans and ghosts travel with it. `BlocksView.planMove` simulates the result first; whitespace-only fix-ups put the separators back (last block without a trailing newline, single-newline separators) and `EditorSurface.squashHistory` folds the move and fix-ups into one undo step. A refused move (it would split a span or ghost) changes nothing and shows the model's message in the always-rendered `.te-blocks-notice-region` live region. No Move up on the first block, no Move down on the last (keys are no-ops). An open editor is committed first, so drafts are applied or kept, never lost; focus follows the moved card.
